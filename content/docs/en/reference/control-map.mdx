## About this map

This page maps JamJet's open-source controls to three public frameworks for agent security and governance. Every row names the component that does the work, the version or pull request it ships in, and its status. A gap is listed as a gap. Where a control only partly meets a framework item, the row says what is missing.

Checked against the sources and code below on 2026-10-11. A mapping is not a certification or an audit. None of these frameworks certifies products, and meeting a row here does not by itself meet a framework item in your deployment.

### Status values

| Status | Meaning |
|---|---|
| Implemented (released) | In a published package or tagged release listed under Components. |
| Implemented (unreleased, PR) | Merged to main and tested, but not in a published package or tagged release yet. The row names the pull request. Do not rely on it until it ships. |
| Partial | Covers part of the framework item. The Notes column says what is missing. |
| Not covered | JamJet has no control for this item. Use another control. |

### Scope

The map covers the open-source runtime and libraries listed below. JamJet Cloud is not mapped on this page.

**The runtime is single-tenant today.** The API layer scopes requests by the token's tenant, but the engine runs every workflow in tenant `default`, and a token of any other tenant is refused. No row on this page claims isolation between tenants. The [security guide][sec-guide] lists what would have to change.

## FINOS AI Governance Framework

Source: [finos/ai-governance-framework][finos-repo] at commit [`a149dd1`][finos-commit] (2026-10-07). Version 2.0 ([FINOS announcement][finos-v2], November 12, 2025) added six agentic risk and mitigation pairs: risks ri-24 to ri-29 and mitigations mi-18 to mi-23. Two mitigations were added after v2.0 and are marked `doc-status: Draft` in the repository: mi-24 and mi-25.

JamJet contributed mi-24, Human-in-the-Loop Action Approval Gate ([finos/ai-governance-framework#339][finos-339], merged 2026-10-07). It is mapped in detail in the next section.

| Mitigation (mitigates) | JamJet control | Component and version | Status | Notes |
|---|---|---|---|---|
| mi-18 Agent Authority Least Privilege Framework (ri-24, ri-18) | Roles on tokens, policy that blocks tools or requires approval, model allowlist; Agent Card tool and delegation lists | runtime 0.5.0; card lists in [jamjet #145][pr-145] | Partial | No time-bounded or context-adjusted agent privileges, and no per-agent credentials. |
| mi-19 Tool Chain Validation and Sanitization (ri-25, ri-10, ri-24) | Policy check before dispatch; guardrails checks on tool inputs and outputs; approval bound to the tool calls a model chose | runtime 0.5.0, guardrails 0.4.1, [jamjet #142][pr-142] | Partial | No parameter schema validation by the engine and no tool-sequence rules. |
| mi-20 MCP Server Security Governance (ri-26, ri-8, ri-1) | Central policy point for MCP calls, drift and shadowing detection, trust baseline for servers | ext-authz 0.2.0, mcp-threat 0.1.0, mcp-shim 0.2.1 | Partial | No vendor vetting, encryption or server isolation. Definition pinning in the shim ([jamjet-policy #12][pr-policy-12]) and Cedar policies in ext-authz ([jamjet-policy #14][pr-policy-14]) are merged, not yet published. |
| mi-21 Agent Decision Audit and Explainability (ri-24, ri-25, ri-22) | Hash-chained, HMAC-signed audit log of policy decisions, approvals and lifecycle events; AgentBoundary receipt per Python agent turn | runtime 0.5.0 [audit][audit], Python SDK 0.12.0 ([governance](/open-source/governance)) | Partial | No capture of model reasoning. In 0.5.0 the signature is a symmetric MAC, so it shows tampering but not who signed. Ed25519 signing is in [jamjet #145][pr-145], not yet released. |
| mi-22 Multi-Agent Isolation and Segmentation (ri-28, ri-24, ri-27) | none | none | Not covered | The runtime is single-tenant and does not isolate agents' state or processes. |
| mi-23 Agentic System Credential Protection Framework (ri-29, ri-24, ri-26) | `secrets` check redacts credentials in model inputs and replies; token-passthrough detection for MCP tool arguments | guardrails 0.4.1, mcp-threat 0.1.0 | Partial | No just-in-time credential delivery, rotation or isolated credential store. `secrets` matches issuer prefixes only. |
| mi-24 Human-in-the-Loop Action Approval Gate (ri-24, ri-18, ri-22) | Approval gate in the runtime | runtime | Partial | See the next section, item by item. |
| mi-25 Skill/Plugin Integrity and Governance (ri-30, ri-8, ri-9) | Scan repository rule files for hidden Unicode instructions | guardrails `scan`, [jamjet-guardrails #43][pr-gr-43] | Partial (unreleased, PR #43) | In the untagged 0.5.0. Covers part of automated pre-screening only. No allowlisting, provenance, dependency control or sandboxing. |

## mi-24 item by item

Each row is a principle or requirement from the [mi-24 text][finos-mi24]. The runtime behavior is described in the [HITL guide][hitl-guide].

| mi-24 requirement | JamJet behavior | Component and version | Status | Notes |
|---|---|---|---|---|
| Gate the action with its resolved parameters | The approval binds a digest over the dispatched payload, the node occurrence and the node definition. The approver must echo it (400 if missing, 409 if stale). | runtime, [jamjet #142][pr-142] | Implemented (unreleased, PR #142) | Released 0.5.0 gates a node, but the approval is not bound to its payload. |
| Enforce at a choke point the agent cannot skip | One guard decides for the in-process worker, the claim route and completion. A gated node is withheld from claim until approved. | runtime, [jamjet #142][pr-142] | Implemented (unreleased, PR #142) | Complete mediation of credentials and network egress is outside JamJet. |
| Fail closed | A decision after the deadline is refused; an unreadable deadline counts as passed; an event kind the build cannot read covers no approval and stalls the run. The Python SDK fails closed on approval in process. | runtime, [jamjet #144][pr-144]; Python SDK, [jamjet #133][pr-133] | Implemented (unreleased, PR #144) | Actions no pattern matches run without approval, as mi-24 expects for baseline controls (mi-18). |
| Durable, resumable approval state | Pending approvals are events in the run's durable log and survive restarts. | runtime 0.5.0 | Implemented (released) | |
| Idempotent side effects | An idempotency key is reserved before a tool effect fires. | runtime 0.5.0 ([#125][pr-125], [#128][pr-128]) | Partial | Firing is at-least-once. There is no `outcome-unknown` state for a downstream that cannot honor the key. |
| Single-effect resolution; late decisions rejected | One outcome per request, checked in the same step as the append. A decision at or after `expires_at` is refused with 409. | runtime, [jamjet #144][pr-144] | Implemented (unreleased, PR #144) | |
| Named oversight pattern (maker-checker, dual authorization) | Maker-checker: the run's initiator cannot approve, and the approver is the authenticated token principal. | runtime, [jamjet #142][pr-142] | Partial (unreleased, PR #142) | No N-of-M or two-person approval. Shared identities are prevented only by issuing one token per human. |
| Bounded waiting and escalation | `approval_timeout_secs` expires a request as a rejection by `system:deadline`. `escalate_after_secs` records `approval_escalated` once. | runtime, [jamjet #144][pr-144] | Implemented (unreleased, PR #144) | When several policy levels set a timeout, the shortest applies. No built-in notifier. The escalation event is the hook for one. |
| Modification is a new action | An approval carrying a `state_patch` is refused. Reject and re-run with different input. | runtime, [jamjet #142][pr-142] | Implemented (unreleased, PR #142) | |
| Revalidate before release | If the payload differs from the approved one at dispatch, the node asks again. | runtime, [jamjet #142][pr-142] | Partial (unreleased, PR #142) | External predicates (account state, limits, policy version) are not re-checked by JamJet. |
| Decision-grade channel showing the digest | REST, CLI (`jamjet approvals`, `--show-basis`), Python SDK and Java SDK take and show the digest. | runtime and SDKs, [jamjet #142][pr-142], Java SDK [jamjet #143][pr-143] | Implemented (unreleased, PR #142) | |
| Standing approval and pre-authorization | none | none | Not covered | An approval covers one request and its retries. |
| Tamper-evident record | Requests (with digest and deadline), decisions, expiries and escalations are sealed into the hash-chained audit log. A failed seal is recorded as `audit_seal_failed`. | runtime, [jamjet #144][pr-144] | Implemented (unreleased, PR #144) | Chain verification cannot see entries removed from the end of the log. |
| Non-repudiation (NIST AU-10) | With `JAMJET_AUDIT_SIGNING_MODE=ed25519`, every audit entry, decisions included, is signed with a key only the runtime holds. The public key is in `/.well-known/did.json` as `#audit-key`, and `jamjet.runtime_audit` verifies an export offline. | runtime, [jamjet #145][pr-145] | Partial (unreleased, PR #145) | The runtime signs, not the approver, who is named by API token. The default HMAC-SHA256 mode uses one shared key, so whoever can verify can also sign. |

## NIST CAISI and NCCoE themes

Sources: NIST CAISI [AI Agent Standards Initiative][caisi], announced February 17, 2026, and the NCCoE concept paper [Accelerating the Adoption of Software and AI Agent Identity and Authorization][nccoe] (initial public draft, February 5, 2026). The rows use the concept paper's question areas: identification, authentication, authorization, auditing and non-repudiation, and prompt injection.

| Theme | JamJet control | Component and version | Status | Notes |
|---|---|---|---|---|
| Identification | The runtime serves a `did:web` document listing active registered agents. Receipts name the actor, agent, model and tool. | runtime 0.5.0 [`/.well-known/did.json`][routes]; Python SDK 0.12.0 [receipts][py-receipts] | Partial | Agents do not hold their own credentials. API tokens identify the caller, not an agent instance. |
| Authentication | Bearer API tokens with roles for people and services calling the runtime | runtime 0.5.0 [auth][auth] | Implemented (released) | Applies outside dev mode. |
| Authentication | MCP bridge requires the same token auth outside dev mode | runtime, [jamjet #142][pr-142] | Implemented (unreleased, PR #142) | |
| Authentication | Key issuance, rotation and revocation for agents | none | Not covered | |
| Authorization | Deterministic policy decision before each node; per-route roles; operator-only tenant policy | runtime 0.5.0; route enforcement in [jamjet #142][pr-142] | Implemented (unreleased, PR #142) | The policy engine itself is released in 0.5.0. |
| Authorization | Cedar policies evaluated next to YAML rules at the ext-authz decision point; an evaluation error blocks the call | @jamjet/cedar, ext-authz, [jamjet-policy #14][pr-policy-14] | Implemented (unreleased, PR #14) | For MCP tool calls through ext-authz. The runtime's policy engine does not read Cedar. |
| Authorization: binding agent action to human approval | Approver is the token principal, distinct from the initiator, and approves a digest of the exact action | runtime, [jamjet #142][pr-142] | Implemented (unreleased, PR #142) | |
| Authorization: delegation "on behalf of" | none wired | runtime | Not covered | See the ASI03 row on `oauth.rs`. |
| Auditing | Hash-chained, HMAC-signed audit log; `verify_chain` reports an edited entry, a broken link, and a missing or invalid signature | runtime 0.5.0 [audit][audit]; Python SDK 0.12.0 [audit][py-audit] | Implemented (released) | Without `JAMJET_AUDIT_SIGNING_KEY` entries are left unsigned and reported as unsigned. |
| Non-repudiation | Ed25519 signature on every runtime audit entry, verifiable offline with the public key the runtime publishes | runtime, [jamjet #145][pr-145] | Partial (unreleased, PR #145) | Shows the runtime wrote the entry. Approvers and agents do not sign. HMAC remains the default mode. |
| Non-repudiation | Ed25519 COSE_Sign1 envelope over AgentBoundary receipts, with an offline verifier that lists what it did not check | AgentBoundary, [agentboundary #5][pr-ab-5] ([SCITT alignment][ab-scitt]) | Implemented (unreleased, PR #5) | The JamJet runtime does not emit AgentBoundary receipts. Signer identity is established only by the keyring you pass, and nothing is registered with a transparency service. |
| Prompt injection | Structural injection checks; `url-exfiltration` and `secrets` limit what an injected agent can carry out | guardrails 0.4.1 | Partial | Does not read meaning. Approval gates and policy limit what an injection can do; they do not detect it. |
| Tracking data flows | Each guardrails verdict records the SHA-256 of the text it inspected; receipts carry an `arguments_hash` | guardrails 0.4.1; AgentBoundary 0.1.0 | Partial | No end-to-end provenance of prompts and data sources. |
