## What the starter does

`dev.jamjet:jamjet-spring-boot-starter` adds advisors to the `ChatClient` that Spring AI auto-configures. With it on the classpath, every call through that `ChatClient` is recorded on the JamJet runtime as an execution with an event log: the prompt, the response and the outcome. Calls you mark can be held until a reviewer approves them.

The model call runs in your JVM. The runtime holds the record. It does not re-run, resume or replay Spring AI calls, so a call that was in flight when your process stopped is not continued after a restart. Its execution stays on the runtime without an outcome event.

By default a call the runtime cannot record is refused before the model is called. See [When the runtime is unavailable](#when-the-runtime-is-unavailable).

## Setup

### 1. Add the dependency

#### Maven

```xml
<dependency>
    <groupId>dev.jamjet</groupId>
    <artifactId>jamjet-spring-boot-starter</artifactId>
    <version>0.2.0</version>
</dependency>
```

#### Gradle (Kotlin DSL)

```kotlin
implementation("dev.jamjet:jamjet-spring-boot-starter:0.2.0")
```

#### Gradle (Groovy DSL)

```groovy
implementation 'dev.jamjet:jamjet-spring-boot-starter:0.2.0'
```

You also need a Spring AI model starter (for example `spring-ai-starter-model-openai`), so that Spring AI auto-configures a `ChatClient.Builder`.

### 2. Start the JamJet runtime

```bash
docker run -p 7700:8080 -e JAMJET_DEV_MODE=1 jamjetdev/jamjet:0.5.0
```

Dev mode turns off authentication. This image keeps state in memory. The `jamjet-server` binary defaults to a SQLite file in its working directory, which survives restarts. Outside dev mode, set `spring.jamjet.api-token`.

### 3. Configure

```properties
spring.jamjet.runtime-url=http://localhost:7700
# spring.jamjet.api-token=${JAMJET_API_TOKEN}   # required outside dev mode
```

The token decides the tenant. There is no separate tenant setting: `spring.jamjet.tenant-id` is ignored and logs a warning at startup.

### 4. Use the ChatClient as normal

```java
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;

@SpringBootApplication
public class MyApp {

    public static void main(String[] args) {
        SpringApplication.run(MyApp.class, args);
    }

    @Bean
    ChatClient chatClient(ChatClient.Builder builder) {
        return builder.build(); // JamJet advisors are added by auto-configuration
    }

    @Bean
    CommandLineRunner demo(ChatClient chatClient) {
        return args -> System.out.println(
                chatClient.prompt("Summarize AI trends").call().content());
    }
}
```

The advisors are added by a `ChatClientCustomizer`, so they apply only to clients built from the auto-configured `ChatClient.Builder`. A client built another way (`ChatClient.create(model)`, `ChatClient.builder(model)`) is neither recorded nor gated. Add the advisor beans to it yourself with `.defaultAdvisors(...)`.

## What gets recorded

| Advisor | What it does on the runtime |
|---------|-----------------------------|
| `JamjetDurabilityAdvisor` | Registers the `spring-ai-chat` workflow once (`POST /workflows`), starts one execution per call (`POST /executions`) before the model is called, and appends a `spring_ai.completed` event with the outcome (`completed` or `failed`). |
| `JamjetAuditAdvisor` | Appends the prompt and the response as `spring_ai.prompt` and `spring_ai.response` events. Turn the text off with `spring.jamjet.audit.include-prompts=false` and `spring.jamjet.audit.include-responses=false`. |
| `JamjetApprovalAdvisor` | Opt in with `spring.jamjet.approval.enabled=true`. Holds calls that ask for approval until a reviewer decides. See [Human approval](#human-approval). |

The workflow has one node, a `wait` on the `spring_ai.completed` event, which the advisor sends when the call ends. Each `spring_ai.*` record is an `external_event_received` event on the call's execution, with the name as its correlation key.

The advisor puts the execution id in the advisor context under `jamjet.execution.id` (`JamjetDurabilityAdvisor.EXECUTION_ID_KEY`). Read a call's record back with `GET /executions/{id}/events`, or from Java with the auto-configured client:

```java
import dev.jamjet.spring.client.JamjetRuntimeClient;
import dev.jamjet.spring.client.model.ExecutionEvent;
import java.util.List;

List<ExecutionEvent> events = runtimeClient.listEvents(executionId);
for (ExecutionEvent event : events) {
    if (event.isExternalEvent("spring_ai.response")) {
        System.out.println(event.payload());
    }
}
```

## When the runtime is unavailable

With the default `spring.jamjet.on-runtime-error=fail-closed`, the result depends on when the runtime fails:

| When | What fails to record | Result |
|------|----------------------|--------|
| Before the model is called | workflow registration, starting the execution, the `spring_ai.prompt` event, the approval request | The call is refused with `JamjetGovernanceException` and the model is not called. |
| After the model returned | the `spring_ai.response` or `spring_ai.completed` event | `JamjetRecordingException`. The model call completed, so any effect it had has happened. Only its record is missing. The runtime's error is the cause. |
| After the model threw | the `failed` outcome | The model's own exception, with a `JamjetRecordingException` attached as suppressed. |

A `runtime-url` that does not point at the runtime API counts as a failure. Any answer that is not JSON is an error, never data.

To let calls run unrecorded instead, opt in:

```properties
spring.jamjet.on-runtime-error=fail-open
```

Fail-open logs a warning for every call it lets through.

### Streaming

In fail-closed mode a streaming call (`.stream()`) is refused before the model runs unless you allow it:

```properties
spring.jamjet.allow-streaming=true
```

An allowed stream records the whole streamed text as `spring_ai.response` and an outcome of `completed`, `failed` or `cancelled`. A stream's record can only be written after its output was delivered, so a fail-closed record failure on a stream arrives as an error at the end of the stream, after the chunks.

## Human approval

```properties
spring.jamjet.approval.enabled=true
spring.jamjet.approval.timeout=30m
```

Mark a call as needing approval:

```java
import dev.jamjet.spring.advisor.JamjetApprovalAdvisor;

String answer = chatClient.prompt("Send the wire")
        .advisors(a -> a.param(JamjetApprovalAdvisor.REQUIRES_APPROVAL_KEY, true))
        .call()
        .content();
```

The call records `spring_ai.approval_requested` on its execution and blocks until a reviewer decides through the approval endpoints:

```bash
# Calls waiting for a decision, each with its prompt and content_digest
curl -u reviewer:secret http://localhost:8080/jamjet/approvals/pending

# Decide
curl -u reviewer:secret -X POST http://localhost:8080/jamjet/approvals/{executionId} \
  -H 'Content-Type: application/json' \
  -d '{"decision":"approved","content_digest":"<from /pending>","comment":"checked"}'
```

Only `"approved"` lets a call through. A call that is rejected or times out throws `ApprovalRejectedException` and the model is not called. A timeout always counts as a rejection.

### A decision is bound to the request that was reviewed

`/pending` shows each request and a `content_digest` over what the `ChatClient` hands the model: every message's role and text, media, tool calls, tool responses, every readable property of the options object, the tool names and definitions, and the tool context. A decision must echo that digest. Without it the answer is 400, with a different one it is 409, and nothing is recorded.

The digest does not cover default options and tools configured on the `ChatModel` itself (for example `spring.ai.openai.chat.options.*`), because the model merges them inside its own call where an advisor cannot see them. Set options that matter for approval on the `ChatClient` or the request.

The approval advisor runs last among advisors (order `LOWEST_PRECEDENCE - 1`), so changes made by your other advisors are part of what the reviewer sees.

Only one decision applies to a call. A second or late decision gets 409 and records nothing.

### What an approval does not cover

Spring AI runs the tool-calling loop inside the model call. After approval the model can call the tools it was offered, and those calls are not reviewed one by one. To gate the actions themselves, run them as runtime-governed tools under the runtime's own approval policy, which holds each call until it is approved. See [Approvals](/open-source/approvals).

### Reviewers must be authenticated

The approval endpoints are registered only when Spring Security is on the classpath. Both `GET /pending` and decisions require:

- **An authenticated principal.** A request with no principal, an anonymous authentication, or an authentication that is not authenticated gets 401 and releases nothing. A remember-me login is refused too unless `spring.jamjet.approval.allow-remember-me=true`. The approver recorded on the runtime is this principal. The request body cannot name it.
- **The approver authority.** The controller requires `ROLE_JAMJET_APPROVER` (configurable with `spring.jamjet.approval.required-authority`) and answers 403 without it. A principal that is not a Spring Security `Authentication` has no authorities the controller can read and is refused.
- **Separation of duties.** The principal that started a call cannot approve it (403). JamJet captures the initiator from the security context before any thread hop: on the calling thread for `.call()`, and at subscription for `.stream()`. A caller-supplied `jamjet.approval.initiator` param is ignored and logged.

The initiator is lost when the call runs on a thread that does not carry the caller's `SecurityContext`, for example an `@Async` method or a plain executor. Use `DelegatingSecurityContextExecutor` or `SecurityContextHolder` propagation. When the initiator is unknown, the request and decision events record `initiator_known: false`, and the call can be rejected but not approved unless `spring.jamjet.approval.allow-unknown-initiator=true`. The check compares principal names exactly, so make sure one person has one name across your authentication sources.

Restrict the endpoints in your filter chain as well:

```java
import org.springframework.context.annotation.Bean;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Bean
SecurityFilterChain approvals(HttpSecurity http) throws Exception {
    return http
            .securityMatcher("/jamjet/approvals/**")
            .authorizeHttpRequests(a -> a.anyRequest().hasRole("JAMJET_APPROVER"))
            .httpBasic(Customizer.withDefaults())
            .csrf(csrf -> csrf.disable()) // see the note below
            .build();
}
```

Turning CSRF off is acceptable here only because the decision endpoint accepts `application/json` bodies only, so a cross-site form post is refused (415) even though browsers resend cached Basic credentials. If reviewers sign in with a session or form login, keep CSRF on and send the token with each POST.

For local development, `spring.jamjet.approval.controller.allow-unauthenticated=true` registers the endpoints even without Spring Security and logs a warning at startup. It switches off every reviewer check, also when Spring Security is present. Decisions from anyone who did not authenticate are recorded with approver `unauthenticated` and `authenticated: false`, and anyone who can reach the application can approve its calls.

### Approvals the runtime holds

The runtime records the identity of the token that sends a decision and enforces separation of duties on it, so the application never forwards decisions with its own token. If the runtime holds a pending approval on a waiting call's execution, `/pending` lists it read-only, with its `action_digest` and the command to run with your own runtime token:

```bash
jamjet approve exec_... --decision approved --node-id pay --action-digest <digest>
```

### How decisions are recorded

A decision is appended to the call's execution as a `spring_ai.approval_decision` event (approver, whether authenticated, the initiator when known, comment) before the call is released. If it cannot be recorded, the endpoint answers with the runtime's status (or 502) and message, and the waiting call is released as rejected. If a decision is recorded but the call stopped waiting before it could be delivered, the endpoint answers 409 and appends a `spring_ai.approval_decision_void` event, so the record never claims a decision that did not apply.

### Marked calls never run ungated

On a `ChatClient` built from the auto-configured `ChatClient.Builder`, `JamjetApprovalGuard` is auto-configured on its own, independently of `durability-enabled` and `approval.enabled`. It refuses a call marked as requiring approval before the model runs when no approval advisor is on the client. A client built any other way (`ChatClient.create(model)`, `ChatClient.builder(model)`, your own `ChatClient.Builder` bean, or with `spring.ai.chat.client.enabled=false`) gets no guard, and the marker does nothing there. Add `JamjetApprovalGuard` and `JamjetApprovalAdvisor` to it yourself. A call whose execution could not be started (the runtime failed open) is rejected by the approval advisor.

## Runtime audit log

`JamjetAuditService` reads the runtime's audit log (`GET /audit`), where the runtime seals approval decisions it receives. The prompt, response and outcome events the advisors record live in each execution's event log; read them with `JamjetRuntimeClient.listEvents(executionId)`.

```java
import dev.jamjet.spring.audit.JamjetAuditService;
import dev.jamjet.spring.client.model.AuditEntry;
import java.util.List;

List<AuditEntry> trail = auditService.fullTrail(executionId);
trail.forEach(e -> System.out.println(e.createdAt() + " " + e.eventType() + " " + e.actorId()));
```

## Testing

```xml
<dependency>
    <groupId>dev.jamjet</groupId>
    <artifactId>jamjet-spring-boot-starter-test</artifactId>
    <version>0.2.0</version>
    <scope>test</scope>
</dependency>
```

### Assert on a recorded execution

`@ReplayExecution` loads an execution's state and event log from a runtime before the test runs and passes it in as a `RecordedExecution`. Nothing is re-run and no model is called. Point the extension at the runtime that holds the execution with the `spring.jamjet.runtime-url` system property (default `http://localhost:7700`). The extension sends no API token, so the runtime must be in dev mode.

```java
import dev.jamjet.spring.test.AgentAssertions;
import dev.jamjet.spring.test.JamjetReplayExtension;
import dev.jamjet.spring.test.RecordedExecution;
import dev.jamjet.spring.test.annotations.ReplayExecution;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import java.util.concurrent.TimeUnit;

@ExtendWith(JamjetReplayExtension.class)
class RecordedCallTest {

    @Test
    @ReplayExecution("exec_abc123")
    void callWasRecorded(RecordedExecution execution) {
        AgentAssertions.assertThat(execution)
                .completedSuccessfully()
                .hasEvent("external_event_received")
                .completedWithin(30, TimeUnit.SECONDS);
    }
}
```

Event names are the runtime's `kind.type` tags (`node_completed`, `node_failed`, `external_event_received`). `hasEvent` also accepts the PascalCase form. `@ReplayExecution(value = "...", forkAtNode = "node")` cuts the event log after that node's completion.

`AgentAssertions` also offers `failedWith`, `wasCancelled`, `costLessThan`, `usedTool`, `usedToolTimes`, `didNotUseTool`, `toolCallCount`, `nodeCompleted`, `nodeRetried`, `nodeCount`, `outputContains`, `outputMatches`, `outputSatisfies` and `eventCount`. Tool, cost and output assertions read events that runtime-run workflows emit (`tool_called`, `cost_usd`, node outputs). A Spring AI call's execution has none of those, because its model call and tools run in your application.

### A runtime container for tests

`@WithJamjetRuntime` on a test class starts `JamjetTestContainer` (`jamjetdev/jamjet:0.5.0` in dev mode) for the class and points the extension at it. The container starts empty. For a Spring test context, `JamjetTestContainer` also has `applyTo(DynamicPropertyRegistry)` to set `spring.jamjet.runtime-url`.

### Deterministic model stubs

`DeterministicModelStub` is a `ChatModel` that answers by pattern, with no LLM calls:

```java
import dev.jamjet.spring.test.DeterministicModelStub;

var stub = DeterministicModelStub.builder()
        .onPromptContaining("weather", "Sunny, 72F")
        .defaultResponse("I don't know")
        .build();
```

The first matching pattern wins, and `defaultResponse` answers the rest. The stub records its calls (`getCallCount()`, `getCalls()`, `reset()`). Its `stream()` returns a single-element `Flux`.

## Observability

When Micrometer is on the classpath and a `MeterRegistry` bean exists, the starter registers a `JamjetMicrometerBridge` bean (`spring.jamjet.observability.micrometer`, default `true`, prefix `spring.jamjet.observability.metric-prefix`, default `jamjet`). With `spring.jamjet.observability.opentelemetry=true` and an OpenTelemetry `Tracer` bean, it registers a `JamjetOtelBridge`. In 0.2.0 the advisors do not call either bridge. They are helpers with methods such as `recordExecutionCompleted(status, duration)` and `startExecutionSpan(executionId, workflowId)` that you call from your own code.

## Configuration

| Property | Default | Description |
|----------|---------|-------------|
| `spring.jamjet.runtime-url` | `http://localhost:7700` | JamJet runtime URL |
| `spring.jamjet.api-token` | none | Bearer token for the runtime. The token decides the tenant |
| `spring.jamjet.durability-enabled` | `true` | Enable the starter |
| `spring.jamjet.on-runtime-error` | `fail-closed` | `fail-closed` refuses calls the runtime cannot record. `fail-open` runs them unrecorded |
| `spring.jamjet.allow-streaming` | `false` | In fail-closed mode, allow `.stream()` calls |
| `spring.jamjet.workflow-id` | `spring-ai-chat` | Workflow the durability advisor registers |
| `spring.jamjet.audit.enabled` | `true` | Add the audit advisor |
| `spring.jamjet.audit.include-prompts` | `true` | Record prompt text |
| `spring.jamjet.audit.include-responses` | `true` | Record response text and token usage |
| `spring.jamjet.approval.enabled` | `false` | Add the approval advisor and endpoints |
| `spring.jamjet.approval.timeout` | `30m` | How long a call waits for a decision (`500ms`, `30s`, `30m`, `2h`, ISO-8601. A bare number is minutes) |
| `spring.jamjet.approval.default-decision` | `rejected` | Deprecated. A timed-out call is always rejected, and any other value fails at startup |
| `spring.jamjet.approval.required-authority` | `ROLE_JAMJET_APPROVER` | Authority a reviewer needs to list or decide approvals |
| `spring.jamjet.approval.allow-unknown-initiator` | `false` | Allow approving a call whose initiator could not be determined |
| `spring.jamjet.approval.allow-remember-me` | `false` | Accept a remember-me login as a reviewer |
| `spring.jamjet.approval.controller.allow-unauthenticated` | `false` | Local development only. Registers the approval endpoints without Spring Security and switches off every reviewer check |
| `spring.jamjet.connect-timeout-seconds` | `10` | Connection timeout |
| `spring.jamjet.read-timeout-seconds` | `120` | Read timeout |

## Upgrading from 0.1.0

0.1.0 called `/api/v1/...` routes the runtime never served. The runtime answered them with its web UI (`200 text/html`), the advisors logged a warning and carried on, and nothing was recorded. 0.2.0 calls the runtime's real routes and refuses calls it cannot record unless you set `spring.jamjet.on-runtime-error=fail-open`. Other changes to check:

- `spring.jamjet.tenant-id` is ignored. Use a token issued for the tenant.
- `spring.jamjet.approval.default-decision` accepts only `rejected`.
- The approval endpoints need Spring Security, an authenticated reviewer with the approver authority, and the `content_digest` from `/pending`. A `user_id` in the decision body no longer names the approver.
- `ExecutionEvent` and `ExecutionState` follow the runtime's field names (`kind`, `created_at`, `current_state`, `started_at`).
